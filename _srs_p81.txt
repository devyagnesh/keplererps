15.7 Known cPanel constraints and how the product handles them
Constraint Product response
No SSH on some plans A web-based installer and updater performs everything artisan would do —
migrations, cache clearing, symlink creation — through the browser, protected by a
one-time installation key.
symlink() disabled The installer detects this and falls back to a real directory plus a controller route that
serves public files, so uploads still work.
Process and CPU limits Heavy work — imports, bulk PDFs, large reports, ledger rebuilds — always runs in the
queue in small chunks, never in a web request.
Inode limits Log rotation capped at 14 days; cache files pruned nightly; generated PDFs older than
a configurable period are archived into monthly ZIP files.
No Redis Database and file drivers are the default and are tested as first-class options, not as a
degraded fallback.
Shared MySQL performanceQuery design assumes no query cache; heavy reports use summary tables refreshed
by the scheduler rather than aggregating raw rows on every view.
Email deliverability The default is SMTP through an authenticated provider rather than the server's 
mail() function, because shared-host IP addresses are frequently blacklisted.
