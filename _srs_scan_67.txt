US-M17-07 — As a Super Admin, I want reprinted labels controlled, so that two boxes never carry the same
code.
Acceptance: a reprint reuses the same code, never generates a new one, requires a reason, prints a visible
REPRINT mark, and is logged; a report lists units reprinted more than twice.
US-M17-08 — As a Store Keeper, I want to replace a label that has been torn off a drum, so that the drum
does not become anonymous stock.
Acceptance: the replace action voids the old code, issues a new one, links old to new permanently, and a
later scan of the old code shows "this label was replaced" with the new code rather than a blank error.
US-M17-09 — As an Owner, I want to know instantly which packages of a suspect batch have already gone
out and to whom, so that a recall takes minutes.
Acceptance: from the batch, a package list shows every unit with its status, and for dispatched units the
customer, challan, invoice, vehicle and date; the list exports to PDF and can be sent on WhatsApp to the sales
team.
US-M17-10 — As a Store Keeper, I want physical stock taking done by scanning, so that the annual count
stops taking three days.
Acceptance: a count session records each scanned unit once, then produces a variance report of expected
against found — listing units expected in this location but not scanned, units scanned here but expected
elsewhere, and unknown codes — which posts as a stock adjustment after approval.
