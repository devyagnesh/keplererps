# Rule Reason
A5 Nothing is hard deleted. Every table
uses soft deletes plus a cancellation
reason where relevant.
Audit and statutory record keeping.
A6 Anything that talks to the outside
world (WhatsApp, FCM, email) is
dispatched to a queue, never called
inline in a request.
A slow Meta API must never make the user's Save button hang.
A7 Every document number comes from
the central Numbering Engine, using a
database lock. Numbers are never
generated with max(id)+1.
Prevents duplicate numbers when two users save at the same second.
A8 No raw SQL string concatenation with
user input. Query builder or bound
parameters only.
SQL injection prevention.
A9 All list screens must be server-side
paginated and indexed. No screen may
load more than 100 rows at once by
default.
Shared hosting has limited memory.
A10 Industry-specific behaviour is driven by
configuration, never by 
if ($industry == 'plastic') inside
a service.
Otherwise the codebase becomes eleven products glued together.
